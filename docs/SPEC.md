**Чому `reference/`:** сторінка SoilSim-pH — це JS-застосунок, і агент не зможе надійно «прочитати» її стилі за URL. Без файлів референсу дизайн доведеться вгадувати, а це заборонено (розділ 3).

## 0.2. Порядок роботи

1. Розділ 2 скопіюй у `.cursor/rules/soilsim.mdc` (постійні правила для кожного чату).
2. Кожний етап (розділ 14) запускай **в окремому новому чаті** командою:
   `Прочитай @docs/SPEC.md і @docs/PROGRESS.md. Виконай ЕТАП N. Після завершення онови PROGRESS.md і зупинись для перевірки.`
3. Етап 1 починай у режимі **Plan**, решту — в режимі **Agent**.
4. Після кожного етапу: `npm run check`, коміт у git, перегляд у браузері.

# 1. РОЛЬ, МЕТА, МЕЖІ ПРОЄКТУ

Ти — senior full-stack developer, UI/UX-дизайнер і фахівець із освітніх симуляторів в агрохімії та ґрунтознавстві.

Створи вебзастосунок **SoilSim: Добрива** — самостійний освітній продукт для вивчення мінеральних добрив: склад, фізико-хімічні властивості, поведінка в ґрунті, взаємодія між собою, розрахунок вмісту діючих речовин.

Продукт належить сімейству SoilSim (SoilSim-pH v2.0, автор — Володимир Нікорич, Чернівецький національний університет ім. Ю. Федьковича). Має впізнавану стилістику SoilSim, але власну архітектуру, дані та функціональність.

Це **інтерактивний навчальний інструмент**, а не електронний підручник і не адміністративний інтерфейс із таблицями й формами.

1. Наукова достовірність формул, реакцій, розрахунків.

## 3.3. Шапка та навігація

- Назва: **SoilSim: Добрива**
- Підзаголовок: «Інтерактивний симулятор мінеральних добрив»
- Опис: «Вивчай склад, досліджуй властивості, моделюй хімічні процеси та виконуй агрохімічні розрахунки».
- Перемикач мови (UK/EN), перемикач теми (світла/темна; за замовчуванням — `prefers-color-scheme`), кнопка «Про симулятор», рядок подяки/авторства.
- Текст «Про симулятор» і подяки: використати рядок з SoilSim-pH — «Розробка та адаптація: Володимир Нікорич / Чернівецький національний університет ім. Ю. Федьковича, 2026» — і позначити як `TODO: підтвердити формулювання`. Не вигадувати додаткових осіб чи організацій.
- Чотири вкладки, у кожної своя внутрішня навігація; стан вкладки відображається в `location.hash` (глибокі посилання, кнопка «Назад»).

## 3.4. Формули

Власний компонент `<ChemFormula formula="Ca3(PO4)2" />` — перетворює цифри після символів/дужок на індекси, `^+`/`^-`/`^2+` на заряди, `·` для гідратів. Рівняння — `<ChemEquation>` з масивом реагентів/продуктів (стрілка, умови над стрілкою, ↑/↓).
KaTeX — лише якщо справді потрібен для розрахункових виразів (`M = D·100 / C`), і тільки з ліниві-завантаженням (lazy import). Не додавати MathJax.

# 5. МОДЕЛЬ ДАНИХ

Формат гнучкий, але мусить підтримувати такі можливості.

```ts
type Verification = 'author-provided' | 'computed' | 'verified' | 'needs-review' | 'unknown';

interface Quantity {
  nominal: number | null;      // розрахункове значення за замовчуванням
  min?: number; max?: number;  // діапазон, якщо вихідний перелік дає діапазон
  basis: 'commercial' | 'theoretical';
  status: Verification;
  sourceIds?: string[];
}

type NutrientKey = 'N' | 'P2O5' | 'K2O' | 'CaO' | 'MgO' | 'S' | 'Na2O' | 'Cl';

interface Fertilizer {
  id: string;
  name: { uk: string; en: string };
  synonyms?: { uk?: string[]; en?: string[] };
  group: 'nitrogen' | 'phosphorus' | 'potassium' | 'complex';
  subgroup?: string;                       // напр. water-soluble / citrate-soluble / poorly-soluble
  formula: string | null;                  // null для сумішей і сировини (НЕ вигадувати єдину формулу)
  formulaNote?: { uk: string; en: string };// напр. «умовне подання складу»
  isMixtureOrRawMaterial: boolean;
  grades?: { id: string; label: string; nutrients: Partial<Record<NutrientKey, number>>; nitrogenForms?: NitrogenForms }[];
  nutrients: Partial<Record<NutrientKey, Quantity>>;
  nitrogenForms?: { amide?: Quantity; ammonium?: Quantity; nitrate?: Quantity };
  ions: { cations: string[]; anions: string[]; neutral?: string[] };  // джерело логіки «Детектива» і «Змішувального столу»
  tags: string[];                           // 'hygroscopic','alkaline','acidifying','chloride','ammonium','nitrate','amide','soluble','citrate-soluble', ...
  physical?: { state?: string; appearance?: Text; hygroscopicity?: 'low'|'medium'|'high'|'unknown' };
  solubility?: { water?: SolClass; citrate?: SolClass; citricAcid?: SolClass; byTemperature?: {tC:number; gPer100gWater:number; sourceId:string}[] };
  soil?: { physiologicalReaction?: 'acidic'|'neutral'|'alkaline'|'unknown'; text?: Text; cecInteraction?: Text; mobility?: Text; ballast?: string[] };
  plant?: { uptakeForms?: Text; sensitivities?: Text };
  application?: { methods: string[]; notes?: Text };
  reactions: ReactionRef[];                 // посилання на рівняння з бази реакцій
  description: Text;
  illustration?: { kind: 'svg-generated' | 'asset'; ref: string; license?: string };
  sources: SourceRef[];                     // порожньо = «потребує верифікації»
  reviewFlags?: string[];                   // id записів AGROCHEMICAL_REVIEW
}
```

Правила:
- Незаповнене поле = `null`/відсутнє + статус `unknown`. Заповнювати вигаданим не можна.
- `byTemperature` заповнюється **лише** з `data-sources/solubility.csv` (з обов'язковою колонкою `source` і статусом `verified`). Інакше графік температури для цього добрива не показується.
- Хімічні формули зберігаються як рядки (`"NH4NO3"`), рендер — тільки через `<ChemFormula>`.
- Усі інтерфейсні модулі отримують добриво за `id` з `src/data/fertilizers/index.ts`.

# 9. ВКЛАДКА 2 — ВІРТУАЛЬНА ЛАБОРАТОРІЯ

Кожний експеримент: 1 мета → 2 теорія → 3 параметри → 4 інтерактивний процес → 5 результат → 6 хімічне пояснення → 7 контрольне запитання. Кнопки «Скинути» і «Повторити». Бейдж типу моделі. Без важких декоративних ефектів; поважати `prefers-reduced-motion`.

## 9.1. Робота 1А. Розчинність

Параметри: добриво (з бази), розчинник, об'єм, маса, температура, перемішування, час.

**Розчинники:** вода; 2 % розчин лимонної кислоти; нейтральний розчин цитрату амонію (класичні агрохімічні екстрагенти для класифікації Р-добрив). Для них використовується **якісна** класифікація розчинності з бази (`SolClass`: добре / помірно / малорозчинне / практично нерозчинне / невідомо), а не вигадані числа.

**Логіка:**
- Є верифіковані дані `byTemperature` → кількісна модель: порівняти масу з межею розчинності при заданих T і V; показати залишок, кристалізацію при охолодженні; графік «розчинність від температури».
- Немає даних → лише якісна модель; графік **не** показується; повідомлення «числові дані відсутні».
- Візуалізація: розчинення гранул, прозорість, нерозчинний залишок, осад — лише якщо він передбачений даними.
- Якісне пояснення ендотермічності розчинення (напр. NH₄NO₃, сечовина) — допускається лише як текст без числових значень, якщо відсутні верифіковані величини.

## 9.2. Робота 1Б. Фосфати і pH («Ретроградація фосфору»)

Дві частини, чітко розмежовані бейджами:

**Частина 1 — «Розрахунок».** Діаграма співвідношення форм ортофосфатної кислоти (H₃PO₄ / H₂PO₄⁻ / HPO₄²⁻ / PO₄³⁻) залежно від pH 4–8. Рівняння Гендерсона–Гасселбальха з константами pKa₁ ≈ 2,15; pKa₂ ≈ 7,20; pKa₃ ≈ 12,35 (25 °C, ідеальний розчин; **перевірити за довідником і занести в `sources.ts`**). Показати часткові мольні частки α₀…α₃ і формули розрахунку. pH 4–8: переважно H₂PO₄⁻ нижче ≈ 7,2, далі HPO₄²⁻.

**Частина 2 — «Концептуальна модель».** Для вибраного P-добрива показати схематично:
- кисле середовище: зв'язування з Fe³⁺/Al³⁺ (FePO₄, AlPO₄ — малорозчинні);
- нейтральне: перехід між розчинними й малорозчинними Ca-фосфатами (Ca(H₂PO₄)₂ → CaHPO₄ → …);
- лужне: зростання ролі Ca-фосфатів.
Переходи показувати як **градієнти**, без чітких порогових чисел і без «% засвоюваності». Явно написати: це навчальна схема, не термодинамічна модель ґрунтового розчину. Рівняння з поясненням — із бази реакцій.

## 9.3. Робота 2. «Змішувальний стіл»

**Двигун правил** (`compat-engine.ts`): правила працюють на **іонних тегах і властивостях** (а не на матриці 22×22): напр. `ammonium + alkaline-calcium-material`, `acidic-phosphate + hygroscopic-nitrate`, `Ca²⁺ + SO₄²⁻ (концентровані розчини)`, `Ca²⁺ + H₂PO₄⁻/HPO₄²⁻`, `urea + monocalcium-phosphate` тощо. Кожне правило містить: умови, режим (dry/solution), статус, механізм (текст), рівняння, умови (вологість, температура, час), візуальні ефекти (що саме показати), `sourceIds` / `verification`.
Статуси: **сумісні / сумісні за певних умов / несумісні / недостатньо даних** (за відсутності правила — завжди «недостатньо даних», ніколи «сумісні»).
Заборонено показувати газ, осад або реакцію, якщо це не випливає з правила.

**Режим А — сухе змішування:** хімічна сумісність, гігроскопічність (зниження критичної відносної вологості суміші), злежування, фізична сумісність (гранулометрія, густина), часові обмеження зберігання («змішати безпосередньо перед внесенням»).
**Режим Б — змішування розчинів:** осад, хімічна взаємодія, прозорість, газоподібні продукти — лише коли вони випливають з механізму.

**Обов'язкові приклади (початкові правила):**

| Пара | Режим | Очікувана логіка (для верифікації автором) |
|---|---|---|
| NH₄NO₃ + негашене/гашене вапно (CaO/Ca(OH)₂) | сухий, вологість | Несумісні: 2NH₄NO₃ + Ca(OH)₂ → Ca(NO₃)₂ + 2NH₃↑ + 2H₂O — втрати N; утворення гігроскопічного Ca(NO₃)₂ |
| NH₄NO₃ + мелений вапняк (CaCO₃) | сухий | **Сумісні за певних умов** (у промисловості вапняк/доломіт використовується як наповнювач у КАН, але за високої вологості й тривалого зберігання можливі повільні втрати NH₃) |
| Карбамід + негашене/гашене вапно | сухий, волога | Несумісні/умовно: лужне середовище й вологість прискорюють гідроліз сечовини й втрати NH₃ |
| Суперфосфат + Ca(NO₃)₂ | сухий | Несумісні за практикою: сильна гігроскопічність Ca(NO₃)₂ + кислий суперфосфат → злежування, вологовиділення; (розчини: ризик осадів Ca-фосфатів — див. окреме правило) |
| (NH₄)₂SO₄ + CaCO₃ / Ca(OH)₂ | сухий, волога | Несумісні: втрата NH₃ (напр. (NH₄)₂SO₄ + CaCO₃ → CaSO₄ + 2NH₃↑ + CO₂↑ + H₂O) |
| KCl + K₂SO₄ | обидва | **Сумісні** (спільний іон K⁺, взаємних реакцій немає) — контрольний «негативний» приклад |

**Додаткові рекомендовані пари (не обов'язкові, але корисні для якості):**
- Ca(NO₃)₂ + K₂SO₄ або (NH₄)₂SO₄ у концентрованих розчинах → CaSO₄·2H₂O↓ (гіпс малорозчинний);
- Ca(NO₃)₂ + KH₂PO₄ / NH₄H₂PO₄ у розчині → осади Ca-фосфатів (залежить від pH і концентрації);
- карбамід + NH₄NO₃ (сухе) → різке зростання гігроскопічності суміші;
- карбамід + Ca(H₂PO₄)₂ → утворення аддуктів із виділенням води, злежування;
- (NH₄)₂HPO₄ + лужні Ca-матеріали → втрати NH₃.

Усі ці твердження з розділу позначити в бекенді-даних як `verification: 'needs-review'` до підтвердження автором і джерелами. Не наводити числових значень (критична відносна вологість, швидкості) без джерела.

**UX:** інтерактивний реактор; перетягування (з клавіатурною альтернативою — кнопка «додати до реактора»); пояснення причини для кожного результату; кнопка «Скинути стіл».

## 9.4. Робота 3. «Ґрунтова колонка»

Бейдж: **«Концептуальна модель»**. Шкали без одиниць («умовні одиниці»); жодних квазі-кількісних концентрацій чи глибин вимивання у реальних величинах.

Параметри: добриво (MVP: **KCl** і **NH₄NO₃**), умовна кількість (мало/середньо/багато), тип ґрунту (піщаний / супіщаний / суглинок / глинистий / чорнозем — **якісний рівень ємності вбирання**: низький/середній/високий; пояснити, що це спрощення), інтенсивність опадів (слабка/помірна/сильна).

Логіка (детермінована кроково-автоматична, state machine):
- KCl: KCl → K⁺ + Cl⁻; K⁺ обмінюється з Ca²⁺/Mg²⁺ на ҐВК (K⁺ затримується, витіснені Ca²⁺/Mg²⁺ переходять у розчин); Cl⁻ не затримується (аніон, мало сорбується ґрунтами) і рухається з водою вниз.
- NH₄NO₃: NH₄⁺ поглинається ҐВК (катіонна форма), NO₃⁻ рухомий (аніонна форма); нітрифікація NH₄⁺ → NO₃⁻ як окремий **якісний** крок із поясненням, що вона залежить від температури, вологості, аерації (не моделювати швидкість).
Ступінь затримки залежить лише від якісного рівня ємності вбирання.
Режими: «крок вперед / назад» та «автоматично» (пауза/стоп). Порівняльний режим «катіон vs аніон» поряд.
Контрольне запитання наприкінці.

Бейдж: **«Розрахунок»**. Усі функції — у `calculations.ts`, `mixture-solver.ts`, `chemistry.ts`.

## 10.1. Конвертер діючої речовини

Формула: **M = D · 100 / C**, де M — маса добрива (кг або кг/га), D — маса діючої речовини, C — вміст, %.
Зворотна: **D = M · C / 100**.

- Два напрями: D → M та M → D.
- Вибір елемента (N, P₂O₅, K₂O, CaO, MgO, S…) — лише ті, що є у добрива.
- Для комплексних добрив і марок (КАС, нітроамофоска) — показати всі компоненти одночасно + «супутні поживні елементи».
- Одиниці: г / кг / т; кг/га; перетворення на вході, показ у вибраній одиниці.
- Діапазон вмісту: правило 6.4.
- Показати формулу, підстановку значень, результат, округлення (за замовчуванням 1–2 знаки; показувати кількість значущих цифр).
- Валідація: порожнє поле, від'ємні, нуль у знаменнику, нечислове.
- Збереження останніх параметрів (storage), «Скинути».

## 10.2. Оксидні еквіваленти

Окремий конвертер: P ↔ P₂O₅, K ↔ K₂O, Ca ↔ CaO, Mg ↔ MgO (додатково S ↔ SO₃ та N ↔ NH₃ — опційно).
**Коефіцієнти розраховуються з атомних мас**, а не хардкодяться; відображати як 2,291 / 1,205 / 1,399 / 1,658 (SO₃: 2,497) і обернені 0,4364 / 0,8301 / 0,7147 / 0,6030. Показувати формулу молярних мас у поясненні.
Попередження в інтерфейсі: «% P ≠ % P₂O₅».

## 10.3. «Конструктор NPK»

Компоненти MVP: амофос, DAP, карбамід, аміачна селітра, KCl, K₂SO₄, нітроамофоска (марка обирається). Безводний аміак **не доступний** у змішуванні (зріджений газ): показати причину. Можна додати інші тверді добрива з бази.

**Режим А — вільне конструювання:** маси → склад суміші (кг та %, N : P₂O₅ : K₂O, частки добрив, загальна маса, **баласт/наповнювач** до 100 %), графічний баланс. Підказки сумісності: для вибраних компонентів викликається `compat-engine` (режим «сухе змішування») і показується попередження, якщо пара несумісна або умовно сумісна.

**Режим Б — розв'язання задачі:** вхід — цільовий склад (N, P₂O₅, K₂O, % у суміші), база 100 кг, набір компонентів, дозволений наповнювач (за замовчуванням так).

Алгоритм (`mixture-solver.ts`, **детермінований, без випадкового підбору**):
1. Система: Σ mᵢ·cᵢⱼ/100 = tⱼ·B/100 для j ∈ {N, P₂O₅, K₂O}; mᵢ ≥ 0; Σ mᵢ ≤ B (різниця — наповнювач).
2. Для всіх підмножин компонентів розміру 1…3 розв'язати систему точно (виключення Гаусса/правило Крамера), відсіяти розв'язки з від'ємними масами (допуск ε = 1e-9) і Σ mᵢ > B.
3. Вивести всі допустимі розв'язки (ранжування: менше компонентів; менша маса наповнювача).
4. Якщо розв'язків немає — повідомити причину: (а) надмірна концентрація (потрібна маса > B), (б) відсутній елемент (немає джерела K₂O) , (в) надлишкова залежність (наприклад, амофос неминуче додає N до P₂O₅).
5. Показати систему рівнянь, підстановку, кроки, перевірку (зворотний розрахунок складу).

**Еталони для тестів (Vitest):**
- 100 кг амофосу (12:52:0) + 100 кг KCl (K₂O 60 %) = 200 кг, N 12 кг, P₂O₅ 52 кг, K₂O 60 кг → склад 6 : 26 : 30.
- Ціль 6:26:30, база 100 кг, компоненти амофос + KCl → 50 кг амофосу + 50 кг KCl, наповнювача 0.
- Ціль 8:20:20, база 100 кг, компоненти амофос (12:52:0), аміачна селітра (N 34,4), KCl (K₂O 60 %) → амофос ≈ 38,46 кг, KCl ≈ 33,33 кг, селітра ≈ 9,84 кг, наповнювач ≈ 18,37 кг.
- Ціль 12:26:30, база 100 кг, ті самі компоненти → **немає розв'язку** (потрібно ≈ 117,4 кг), пояснення (а).

# 11. ВКЛАДКА 4 — ПРАКТИКУМ

Це **не** тест із варіантами A/B/C/D. Три режими, кожний має рівні складності (початковий / середній / складний), підказки (зі штрафом у балах), експертне пояснення. Сценарії — у даних (`data/practicum/*.ts`), оцінювання — окремі функції з юніт-тестами.

## 11.1. «Врятуй урожай» (діагностика)
Опис поля: ґрунт, pH, культура, симптоми, відомі показники, історія удобрення. Студент: (1) формулює можливу проблему, (2) обирає елемент, (3) обирає добриво з бази, (4) пише/обирає обґрунтування, (5) враховує супутні іони й властивості ґрунту.
- Візуалізація симптомів — **SVG-схеми** або зображення з обов'язковим полем `license` і `attribution`. **Не** використовувати hotlink'и і не вигадувати «фото».
- Якщо симптоми неспецифічні — сценарій має декілька прийнятних діагностичних гіпотез (оцінюється аргументація, а не «єдина правильна літера»). Мінімум 9 сценаріїв (по 3 на рівень).
- ⚠ Межа: не рекомендувати норм добрив; діагностика й вибір типу добрива, а не розрахунок програми удобрення.

## 11.2. «Лабораторний детектив»
Невідомий зразок із бази (6–8 варіантів за рівнями). Обмежений бюджет досліджень (напр. 4–5).
Тести (результат **обчислюється з `ions` і `tags` добрива**, не хардкодиться): розчинність у воді; реакція з лугом (NH₄⁺ → NH₃, лакмус/запах); якісна реакція на NH₄⁺; Cl⁻ (AgNO₃, білий осад); SO₄²⁻ (BaCl₂, білий осад, нерозчинний у HCl); PO₄³⁻ (молібдатний реактив); **додатково (розширення):** дія кислоти (шипіння → CO₃²⁻, напр. поташ) і **полуменева проба** (K⁺ фіолетовий, Na⁺ жовтий, Ca²⁺ цегляно-червоний), бо вони розрізняють KCl / сильвініт / калійну сіль.
- Нюанси: сечовина з лугом без нагрівання дає слабкий/повільний результат; важкорозчинні фосфати спершу потребують розчинення в кислоті; не всі тести специфічні — логіка завдання враховує неоднозначність (кілька добрив можуть давати однаковий набір результатів).
- Фінал: правильна відповідь + хімічне обґрунтування + аналіз ефективності (скільки тестів було зайвих).

## 11.3. «Агрохімічний аудит»
Текст сценарію розбитий на клікабельні фрагменти (з клавіатурною доступністю). Студент: (1) позначає помилкові рішення, (2) пояснює механізм, (3) пропонує альтернативу. Оцінка: правильно знайдені, хибно позначені, повнота пояснення. Мінімум 10 сценаріїв. Приклади тем: фосфоритне борошно на нейтральному/слабколужному ґрунті (pH 7,5); карбамід на поверхні без загортання; сульфат амонію без урахування підкислення; суміш NH₄NO₃ з гашеним вапном; безводний аміак зверху без загортання; Ca(NO₃)₂ з сульфатами в одному концентрованому баку.

## 11.4. Журнал результатів
`storage.ts` (ключ `soilsim-fert:v1`, версія схеми, міграція, `try/catch` на приватний режим браузера): виконані завдання, результати, спроби, правильні/неправильні рішення, пояснення помилок, час. Без реєстрації.
**Експорт/імпорт**: JSON та CSV; друк (print-stylesheet) для здачі викладачу. Кнопка «Очистити прогрес» із підтвердженням (єдине допустиме підтвердження-діалог).
